# Database Guide - Supabase データベース管理ガイド

このスキルは `supabase/` ディレクトリ配下のデータベース設定とマイグレーションファイルの管理をサポートします。

## 重要な制約事項

**🚨 必ず守ること**:

- **ローカル環境のみ操作**: リモート環境への直接操作は実行しないでください
- **Supabase CLIを使用**: SQLコマンド直接実行ではなく、supabaseコマンドを利用してください
- **ローカルでテスト**: 本番適用前にローカル環境でテスト

## 技術スタック

- **データベース**: PostgreSQL
- **管理ツール**: Supabase CLI
- **環境**: Dockerベースのローカル開発環境

## マイグレーション管理

### 新しいマイグレーションファイルを作成

```bash
# 新しいマイグレーションファイルを作成
supabase migration new {migration_name}

# マイグレーションを適用
supabase migration up
```

### マイグレーションワークフロー

**推奨手順**:

1. **マイグレーションファイル作成**

   ```bash
   supabase migration new add_new_column
   ```

2. **SQLファイル編集**
   - 生成されたファイル: `supabase/migrations/YYYYMMDDHHMMSS_add_new_column.sql`

3. **ローカル環境に適用**
   ```bash
   supabase migration up
   ```

### マイグレーションのベストプラクティス

1. **ファイルは削除しない**: マイグレーションファイルは削除せず、新しいマイグレーションを作成して修正
2. **ローカルでテスト**: 本番適用前にローカル環境で必ずテスト
3. **アトミックに保つ**: 1 つのマイグレーションは 1 つの変更に集中
4. **ロールバック計画**: 必要に応じて逆マイグレーションも用意

## ディレクトリ構造

```
supabase/
├── .branches/        # ブランチ管理
├── .temp/           # 一時ファイル
├── config.toml      # Supabase設定ファイル
└── migrations/      # SQLマイグレーションファイル
    ├── 20241014122732_posts_table.sql
    └── ...
```

## セキュリティとベストプラクティス

- **インデックス**: インデックスは必要に応じて作成。ユーザーからの明示的な指示がない限りマイグレーションファイルには作成しないで
- **外部キー制約**: データ整合性を保つため外部キー制約を設定
- **マイグレーションのバージョン管理**: 全マイグレーションをgitで管理
- **ローカルテスト**: 本番適用前に必ずローカルでテスト

このスキルを使用することで、Supabaseデータベースを安全かつ効率的に管理できます。

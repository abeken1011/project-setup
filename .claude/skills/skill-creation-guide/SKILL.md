## スキルの概要

Agent Skillsは**Claudeの機能を拡張するモジュール型の機能**で、領域特有の専門知識を提供します。指示、メタデータ、スクリプトをパッケージ化し、汎用エージェントを専門家に変えます。

### 3 段階の読み込みモデル

- **レベル 1（メタデータ）**: 常時読み込み（約 100 トークン）
- **レベル 2（指示）**: トリガー時に読み込み（5000 トークン未満）
- **レベル 3（リソース）**: 必要時のみ読み込み

**関連するコンテンツのみがコンテキストウィンドウを占有**されます。

---

## 基本構造

すべてのスキルには、YAMLフロントマター付きの`SKILL.md`ファイルが必要です:

```yaml
---
name: skill-name # 最大64文字、小文字・数字・ハイフンのみ
description: スキルの説明 # 最大1024文字、第三者視点で記述
---
# スキルの内容
```

### ファイル構成例

```
my-skill/
├── SKILL.md      # メイン指示（必須、500行以下）
├── FORMS.md      # 必要時にロードする追加情報
└── scripts/      # 実行可能スクリプト
    └── helper.py
```

---

## コア原則

### 1. 簡潔性が最優先

**コンテキストウィンドウは公共の財産**です。

- SKILL.md は**500 行以下**に保つ
- Claudeが既に知っている情報は含めない
- 必要な情報のみを追加する

### 2. 適切な自由度の設定

| 自由度 | 形式                                | 使用時                         |
| ------ | ----------------------------------- | ------------------------------ |
| **高** | テキストベースの指示                | 複数のアプローチが有効な場合   |
| **中** | 疑似コード/パラメータ付きスクリプト | 推奨パターンが存在する場合     |
| **低** | 特定スクリプト                      | 操作が脆弱で一貫性が重要な場合 |

### 3. 複数モデルでのテスト

Opusは簡潔な指示で動作しますが、Haikuはより詳細なガイダンスが必要です。両方でテストしてください。

---

## 命名規則

**動名詞形（verb + -ing）を使用**: `processing-pdfs`, `analyzing-spreadsheets`

避けるべき名前: `helper`, `utils`, `anthropic`, `claude`

---

## 効果的な説明の書き方

**第三者視点**で、**何をするか**と**いつ使用するか**を含めます:

```yaml
description: PDFファイルの読み取り、フォーム処理、ドキュメント抽出を行います。PDF、フォーム、またはドキュメント抽出について言及している場合に使用してください。
```

## 段階的開示パターン

必要時のみ追加ファイルをロードしてトークン効率を向上:

```
pdf/
├── SKILL.md      # 基本的な指示（常に読み込まれる）
├── FORMS.md      # 詳細（必要時のみ）
└── scripts/      # 実行可能スクリプト（読み込まれない）
    └── extract.py
```

**重要**: SKILL.mdから**1レベル深い参照**のみ。ネストされた参照（A → B → C）は避ける。

---

## ワークフローとフィードバックループ

複雑なタスクでチェックリストを提供し、進捗を追跡可能にします:

```markdown
## タスク実行チェックリスト

1. [ ] データを読み込む
2. [ ] バリデーションを実行する
3. [ ] データを変換する
4. [ ] 結果を保存する
```

**検証ループ**: 実行 → 検証 → エラー修正 → 繰り返す。スクリプトでバリデーションを実装すると信頼性が向上します。

## コンテンツガイドライン

### 時間に敏感な情報を避ける

「2025 年 8 月以降は...」ではなく、「古いパターン」と「推奨パターン」で記述します。

### 一貫した用語

同じ概念に対して一つの用語を選んで統一します。必要に応じて用語集を作成してください。

---

## 実行可能なコード付きスキル

### エラー処理

スクリプト内でエラー条件を明示的に処理します:

```python
def process_file(file_path):
    try:
        with open(file_path, 'r') as f:
            return f.read()
    except FileNotFoundError:
        print(f"エラー: ファイル '{file_path}' が見つかりません")
        return None
```

### 設定パラメータの正当化

マジックナンバーではなく、理由を含めます:

```python
REQUEST_TIMEOUT = 30  # HTTPリクエストは通常30秒以内に完了
MAX_PAGES = 100       # PDFページは通常100ページ以下
```

### ユーティリティスクリプト

コード生成の代わりに事前作成スクリプトを提供し、SKILL.mdから参照します:

```bash
python scripts/extract.py input.pdf
```

## テストと反復

### 評価駆動開発

1. スキルなしでタスクを実行し、課題を把握
2. 3 つのテストシナリオを作成（基本ケース、エッジケース、エラーケース）
3. ベースラインを確立
4. 最小限の指示を書く
5. 評価を実行して反復的に改善

### 複数モデルでテスト

Haiku、Sonnet、Opusで実際にテストしてください。Claude自身がスキル改善に役立ちます。

---

## 避けるべきアンチパターン

### 1. Windowsスタイルパス

常にフォワードスラッシュを使用: `scripts/helper.py` ✅ ではなく `scripts\helper.py` ❌

### 2. 過剰な選択肢

デフォルト+逃げ道パターンを使用します:

```
デフォルトでは方法Aを使用してください。
特別な要件がある場合は、方法Bを検討してください。
```

### 3. 深すぎる参照

SKILL.mdから直接参照できる1レベル深い構造に保ちます。ネストされた参照（A → B → C）は避けます。

### 4. 包括的すぎる説明

Claudeが既に知っていることを繰り返さないでください。プロジェクト固有のパターンのみ記述します。

---

## 提供前チェックリスト

スキルを提供する前に、以下を確認してください:

- [ ] **説明に具体的な主要用語と使用時機を含める**
- [ ] **SKILL.mdは500行以下**
- [ ] **複数ファイルは段階的開示パターンで整理**
- [ ] **スクリプトはエラー処理と検証を含む**
- [ ] **Haiku、Sonnet、Opus で実際にテスト済み**
- [ ] **実際のユースケースで評価済み**
- [ ] **パスはフォワードスラッシュを使用**
- [ ] **用語が一貫している**
- [ ] **時間に敏感な情報を含まない**
- [ ] **参照の深さは1レベルまで**

---

## セキュリティとサポート

**セキュリティ**: 信頼できるソースからのみスキルを使用してください。外部 URL からデータを取得するスキルは特に慎重に扱います。

**サポート環境**: Claude API（プリセット・カスタム対応）、Claude Code（カスタムのみ）、Claude Agent SDK、Claude.ai

---

## まとめ

効果的なスキルを作成するための鍵は:

1. **簡潔に**: 500行以下、必要な情報のみ
2. **具体的に**: 明確な説明と使用時機
3. **段階的に**: 情報を適切に分割
4. **テストする**: 複数モデルで検証
5. **反復する**: 評価を基に改善

このガイドラインに従うことで、効率的で信頼性の高いClaudeスキルを作成できます。
